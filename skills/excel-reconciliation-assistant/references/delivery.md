# CLI与实际交付

先用同一解释器运行`<skill_dir>/scripts/doctor.py`。下面示例中的`<python>`、`<skill_dir>`、`<workspace>`必须换为当前宿主实际路径，不能原样执行占位字符串。规则与来源在工作区；重复`--authorize`参数逐个列出用户已授权的物理文件路径。

```sh
<python> "<skill_dir>/scripts/reconcile_tool.py" run \
  --rules "<workspace>/rules.json" \
  --authorize "<workspace>/旧台账.csv" \
  --authorize "<workspace>/新清单.csv" \
  --output "<workspace>/核对-v001"
```

先预检时将run改为inspect，并使用另一个新目录。预检只登记来源、结构和规则问题，不能据此宣布关联或比较完成。规则校验失败应依错误代码/具体字段修正，不跳过预检错误后声称全量完成。

stdout为可跨终端编码解析的JSON（中文可能以Unicode转义显示）；交付中的Markdown/JSON文件使用UTF-8。关注status、tasks、different_fields、not_comparable_fields、unavailable_formats及files。skill_version来自实际安装目录VERSION。

| 退出码 | 解释 |
| --- | --- |
| 0 | run完整执行或inspect就绪。完整执行仍可能有业务差异、仅一侧记录。 |
| 2 | needs_confirmation/partial，存在歧义、不可比、公式缓存待确认，或部分任务/格式未完成。 |
| 1 | blocked/error，不能作为完整结论。可隔离的读取问题可能生成明确blocked的诊断文件。 |

默认`--timeout 120`包含CLI隔离进程监督；超时停止并不发布完整清单。不要无理由提升全部预算或忽略超限后“取前N行”。

## 阅读与回查

`核对结果.xlsx`先看概览的任务/两侧范围和数量，再筛选差异。工作簿包括规则、来源、例外、独有、待确认、全部唯一匹配对和数值口径分段汇总。有内容才创建明细表，超过2万行明确分片；原文本惰性，长精确数字可能以文本保存。

`核对报告.md`每任务最多摘要20条例外，完整逐字段内容在`工作资料/字段结果.jsonl`；全部选中源行分类在`关联结果.jsonl`。`读取范围.json`保留实际表头/范围/隐藏/筛选/日期系统/阻断信息，即使Excel降级也可追溯。`待确认事项.md`列出需要业务确认的对应关系或解释缺口。

最终`交付清单.json`列实际文件的相对路径、字节数、SHA-256、任务状态和未生成格式。不将原文件默认复制到交付目录。目录复制过程中可能可见`.交付中.json`，以最后发布的有效清单为准。

已有目录（即使为空）拒绝覆盖；改用新版本目录。目录被其他写入者替换或出现链接会停止；清理只处理本次创建且身份匹配的对象，不删除并发文件。源文件变化、全局预算和覆盖失败不得继续拼接旧结果。

给用户的简报说明：本次实际覆盖、业务差异、待确认/未核对范围、生成文件与限制。只链接真实存在的产物，不把退出0翻译成付款/库存/审批已经正确完成。
