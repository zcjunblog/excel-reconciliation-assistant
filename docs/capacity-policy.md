# 首版容量预算与M1测量

本阶段确定拒绝阈值，未认证完整Skill容量。阈值统一列于[规则协议](rules-protocol.md)，实际测量原始记录见[capacity-probe.json](../evidence/m1/capacity-probe.json)。

## 2026-11-06本机探测

环境为macOS arm64、Python 3.12.14。CSV合成50,000行×20列，读取两次并同时物化，共2,000,000个数据单元格；单文件4,145,571字节。读取与物化约0.078秒，进程峰值RSS约157.62MiB。两次读取同一物理文件，受文件缓存影响，不能用该时间推导用户文件全流程时长。

XLSX合成10,000行×10列，压缩411,954字节、解压4,385,278字节，公式/缓存两次只读流式扫描共约0.4674秒。该输入没有复杂样式、巨大共享字符串或业务公式；未测2,000,000单元格的XLSX。

因此保留50,000行/表作为行数预算，同时用2,000,000累计单元格约束宽表和多表；200列、200,000累计记录等不是可以同时取满的独立承诺。20MiB压缩、100MiB单文件解压与250MiB累计解压是保守工程拒绝阈值，**未由本次小文件测试证明这些体积都可在预算内完成**。只根据文件大小无法约束解码后对象开销，还需实际扫描与输出预算。

## 必须继续验证

M2：阈值边界与超限失败、ZIP声明不实、CSV超长记录、XLSX伪维度/远端单元格、大共享字符串、窄范围但大量范围外内容。用实际读计数与流式限制拒绝，不能先分配后检查。

M3：多任务重用表的输入去重计量与比较逐任务计量；在200,000字段比较边界测试唯一键、重复组与Decimal，记录峰值内存、总耗时，核对全量答案。

M4：在100,000明细/2,000,000输出单元格/50MiB三重预算下测试分片、全量内部结果与Excel打开耗时；先估计再写入，实际超限清除暂存XLSX并保留明确失败状态。输出预算是拒绝阈值，未通过导出性能测试。

M6：选真实可用客户端和不同系统重跑已确定样本，记录宿主资源。只有该证据形成后才在README和市场页写实测容量；不能把本页读取探测宣传为“秒级完成大表核对”。

## 重现

在隔离开发环境安装`tools/requirements-m1.txt`，并准备Artifact Tool运行时；运行`tools/probe_m1.mjs`生成忽略目录中的XLSX，再运行`tools/measure_m1.py`。工具仅使用合成数据，不读取用户业务表。机器、文件缓存和库版本会影响时间，证据中的计数应固定，耗时无需相等。
