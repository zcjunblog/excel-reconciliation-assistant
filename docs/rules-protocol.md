# 核对规则协议 v1

状态：M1规则结构冻结；M2读取、M3关联/比较与M4文件交付已实现。机器结构见[JSON Schema](../schemas/reconciliation-rules.schema.json)，合成实例见[案例目录](../examples/README.md)。规则文件为UTF-8 JSON，`schema_version`固定为`1.0`，未知字段拒绝；升级结构必须显式迁移。实际边界见[读取说明](intake.md)、[比较说明](comparison.md)与[交付说明](delivery.md)。

## 输入和实施顺序

M2同时完成CSV与XLSX来源预检，M3先做两表唯一键核对，M4先交付商贸案例端到端，再复用相同流水线完成其余案例和基准表逐对比较。首版每次2至5张逻辑表、1至4个比较任务。每个任务指定自己的基准侧，不跨任务隐式关联、聚合或加总。

`sources`登记物理文件，路径相对规则文件目录解析。执行前宿主确认授权路径；规则中的路径不构成额外授权。拒绝URL、设备文件、目录和未获授权的符号链接目标。相同物理文件只登记一次，执行前后核对SHA-256。CSV仅逗号分隔，默认UTF-8-BOM兼容读取；其他编码需显式提供，严格解码。引号内换行属于同一条CSV记录，原行号以CSV逻辑记录号计，另存物理起止行；不能伪称Excel单元格。

`tables`指定来源、工作表、单行表头、显式矩形数据范围。表头行不在数据范围内。列采用Excel字母位置，并在每个映射上同时提供预期表头；表头不符、同名表头、缺列、CSV宽度不齐均阻断该表，不按“相近列名”修复。CSV工作表值为null。内部空记录照常计入并成为无效键；范围外行另记未选择，范围内排除只接受带原因的原始行号清单。排除行不能静默消失或伪装为缺失记录。空范围、全排除或任一侧读取失败的任务为`blocked`，不能输出零差异通过。

## 映射与类型

一个任务的`fields`包含键字段和待比较字段。`keys`引用字段ID，必须是identifier或text；字段ID不能重复，左右列不能重复绑定。键字段不计入字段比较分母，剩余至少一个待比较字段。字段范围、引用、键合法性、上下文列及条件约束由M2语义预检负责，JSON Schema只校验可表达的结构。

| 类型 | 固定语义 |
| --- | --- |
| identifier | 仅接受文本，保持前导零与大小写。数值型编号包括补零格式一律待确认，不推测原始编号；超过15位的数值编号提示已有精度风险。 |
| text | 只接受文本，不把布尔、数值或错误值静默转字符串。 |
| decimal | 有限十进制，使用Decimal。XLSX保留XML数值词法后解析，CSV需显式`parse_numeric_text:true`。不接受千分位、货币符号、百分号、科学文本、NaN、Infinity或布尔值。负数允许。 |
| date | 原生日期或指定格式文本。两侧格式分别记录，不猜`01/02/2026`。原生日期时间含非零时间时不可直接截断。 |
| datetime | ISO 8601或显式格式，保留时间精度。两侧时区有无或偏移不同进入待确认，首版不换算时区。 |

缺失值只有null与零长度文本。0不是缺失；空格默认不是缺失。`nullable:false`为默认，任一缺失均`not_comparable`；显式true时两侧均缺失可`exact`，附`both_missing`，单侧缺失为`different`。缺映射列始终是结构错误。

规范化仅适用于identifier/text，按`normalize`数组给出的顺序执行`trim`、`casefold`、`nfkc`，不得重复。同一键规则同时应用两侧；规范化后碰撞仍归重复键。原值与规范化值均保留。`tolerance`仅用于decimal，为非负十进制字符串，默认`"0"`；比较差额固定为**比较侧减基准侧**，绝对差不大于容差才在规则内一致，不做显示位数舍入。

decimal字段可声明`context.currency`、`context.unit`，每侧明确给出固定值或上下文列，不能两者混用。上下文列必须非空文本且两侧精确相等，否则该数值字段`not_comparable`、差额null。上下文字段仍可另行作为text字段比较。无上下文的数值仅是无单位数值，不推测金额含义；标称金额字段必须由Agent补充币种依据。无自动换算。汇总只加总同任务、同字段、同单位/币种且可比较的唯一匹配对，另报参与数和排除数；不统计歧义组，也不合并不同字段的差额。

## 关联、比较与计数

先判断有效键，再按规范化后的带类型元组分组，不用拼接字符串构造复合键。任一侧同键多行，则该组两侧全部进入`duplicate_ambiguous`，即使另一侧只有一行；绝不任意配对。一对多、分批交付均按此处理。

关联状态：`unique_matched`、`left_only`/`right_only`、`duplicate_ambiguous`、`invalid_key`。两侧各自满足：

```
included = unique_matched + only + duplicate_ambiguous + invalid_key
selected = included + explicitly_excluded
```

计数单位为记录，不是重复组数；唯一匹配对数在每侧各计一次。对每个唯一匹配对、每个非键字段恰有一个状态：

| 机器状态 | 展示 | 判定 |
| --- | --- | --- |
| exact | 完全一致 | 类型解析后值相等，且未因规范化改变源文本而消除差异。数值`10`/`10.00`是同一值，保留原词法。 |
| within_rule | 规则内一致 | 非零差额落入容差，或原文本不同但显式规范化后相等。 |
| different | 有差异 | 可比较且超出规则；不判断哪一侧业务正确。 |
| not_comparable | 不可比较 | 类型、必填缺失、日期解释、上下文或公式策略不满足。差额必须null。 |

文本原值相同而两侧同时被trim不制造差异，仍为exact。字段总数=`unique_pairs × non_key_fields`，等于四种字段状态之和。差异记录数是含different的匹配对去重数；不可比较记录数是含not_comparable的去重数，二者可能重叠，不能相加当总数。需要互斥行汇总时优先级为not_comparable > different > within_rule > exact。

每条字段结果保留任务ID、键元组、字段ID、两侧CellRef、原类型/值/数值词法/显示格式、规范化值、状态、原因码、十进制差额字符串及规则引用。CellRef包含source_id、table_id、sheet、原行号和列。来源哈希放来源索引，不在每个单元格重复。结构化中十进制一律字符串，禁止JSON浮点替代精确数值。

## 公式和特殊结构

任务级`formula_policy`仅`pending`或`cached`，规则文件须显式写入；Agent未收到其他选择时填pending。任一待比较值来自公式：pending直接not_comparable；cached只比较已保存的非错误缓存，记录`cache_freshness_unverified`。缓存缺失、Excel错误、外部工作簿引用公式均not_comparable，不能两空当一致。公式型键无论策略如何都invalid_key。缺失/错误缓存优先记录具体原因而不只写笼统“公式待确认”。不执行公式、宏、链接，不启动办公软件重算。

隐藏行列与自动筛选行默认包含，披露位置和数量。合并区域与表头/数据范围相交时阻断该表，不向下填充。表头外装饰、范围外合计只按实际选择披露；范围内合计需显式排除。禁止按关键词“合计”自行删行。

## 资源预算与失败方式

下列是M1冻结的首版**拒绝阈值**，不是已通过全容量性能认证；测量依据与后续验收见[容量记录](capacity-policy.md)。所有阈值累计生效，先到者限制：

- 2–5张逻辑表，1–4个任务；单物理文件20MiB。
- 每XLSX解压总字节100MiB，单成员50MiB，累计250MiB，最多10,000个成员。拒绝加密、重复成员名、路径穿越、宏内容和外部工作簿链接。流式实际解压仍计数，不能只信ZIP声明。
- 单表50,000条数据记录、200列；不同逻辑表合计200,000记录、2,000,000个矩形单元格（含空位，排除前计）。同表被多个任务复用，输入预算只计一次，比较预算逐任务计。
- 每次最多200,000个字段比较。读取还需限制所访问XML/CSV的实际扫描记录与单元格，不能仅验证选中小范围或工作簿声明维度。每文件实际扫描不超过200,000行、2,000,000个单元格；M2禁止遍历伪造的XFD/百万空行矩形。
- CSV单逻辑记录1MiB、单单元格32,000字符；XLSX文本相同上限，超限阻断，不截断。
- XLSX明细每片20,000行，整个结果最多100,000条明细、2,000,000个写入单元格、50个明细分片、50MiB文件。规则、概览同样计写入预算。
- M4补充：全交付累计250MiB，包含Excel、报告、JSONL/JSON与清单；内部资料超全局预算也不能交付“完整”结论。阈值不代表暂存副本的总磁盘占用。
- 总执行时限120秒作为可配置宿主预算；超时中止且不登记完整交付。首版不声称不同硬件均能达到此时间。
- M3具体计算拒绝阈值：Decimal系数最多1000位、调整指数绝对值不超过1000；越界字段标不可比并保留原值，不以舍入换取一致。原生ISO日期保留date_lexeme；数值日期源精度超出库可靠保留范围时也不可比。

任务级结构失败只阻断相关任务；全局预算/来源变更/守恒失败则中止整次运行。可以交付已完整核对的独立任务，运行状态必须`partial`，失败任务在概览可见；不得输出整批“核对通过”。导出超预算时不生成半截XLSX，可保存完整结构化资料及容量问题说明，交付清单将XLSX明确标记未生成。

## 版本和输出

配置路径相对规则目录，输出位置由CLI参数给出，不能在规则中指定任意写入路径。生成新版本目录，目录已存在时拒绝覆盖。默认XLSX只列例外字段及未匹配/待确认记录；另设“匹配索引”包含每个唯一匹配对的来源行和四类字段数量。完整逐字段结果始终在工作资料JSONL保存，不复制原文件。不是只保留差异的丢失型导出。

结果与规则引用同一个来源摘要快照。完成后交付清单只列真实存在的文件及哈希；清单本身不自哈希。协议修改、字段解释变化均生成新规则快照和新输出目录，不改写旧结论。
