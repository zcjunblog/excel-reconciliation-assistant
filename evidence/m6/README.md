## 实际发现

负差额工作簿在WPS中显示-2、-10.25和0.20，编号0007/0008保留；选择差异明细P2，公式栏实际显示比较原行3，冻结区域仍可见。库存仅基准侧的SKU0010保留前导零，四行业概览数量/状态与人工预期一致。只读副本与正式展示工作簿均未改变字节。

错误规则草稿含与实际CSV不一致的表头，并把金额容差写为1，与用户明确的0.01冲突。独立执行者实际得到原草稿inspect的partial/header_mismatch，另存修正规则并记录原因，再完成inspect和run；未修改草稿、原CSV或41份Skill资源。正式结果needs_confirmation，2匹配对、6字段比较，重复键/空键保留待确认。原始调用日志与绝对路径仅留在忽略目录，仓库保存归纳与摘要。

性能样本包含反向行序、前导零编号、50处领用人变化与20处金额-0.01变化。独立逐字段验证14930精确/70不同，5000匹配对，工作簿70条例外、全量索引5000行，10份清单文件摘要通过。4.7428秒包含CLI启动、读取、比较、Excel/报告与交付，不含根上下文的后续验证。OS子进程最大RSS119.3MiB不是同时运行整棵进程树的内存，也不是最大容量认证。
