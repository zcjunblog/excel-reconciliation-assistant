# M2 验证记录

日期：2026-11-06。范围：规则预检、安全来源登记、XLSX/CSV读取及来源追溯。M3业务关联/字段比较与M4导出尚未执行。

## 结果与证据

- [verification.json](verification.json)：41个单元测试通过，失败0、错误0；四组合成案例的9张逻辑表全部读取成功，6个物理来源字节不变，M1清单中的14份来源/规则/人工答案摘要全部保持不变。
- 记录生产脚本与测试源文件SHA-256，限定验证代码版本；不把M1人工答案重新生成或改写为实现的输出。测试日志留在忽略目录`outputs/m2-verification/`，不提交临时夹具或开发机路径。
- 同一记录包含两份50,000行×2列合成CSV的生产读取器验证：每份全部50,000行纳入、无排除，来源摘要不变；耗时和整体验证进程峰值RSS见JSON实际记录，重跑数值可能变化。这不是匹配/比较/导出性能，也不代表宽表最大容量。
- 主环境：macOS arm64、Python3.12.14、openpyxl3.1.5。另用系统Python3.9.6 `-S`禁用site-packages，库存CSV两表读取通过且未导入openpyxl。未在Python3.9下运行完整XLSX测试，不宣称所有系统或客户端已兼容。

## 失败测试与独立审查

M2.1规则测试先因缺少rules失败，来源测试先因缺少intake失败；实现后17个测试通过并提交59a3299。M2.2读取测试先因缺少read_tables失败；追加边界和审查回归后全套41个测试通过。

独立只读审查在最初32项通过时复现6项Important，未发现已证实Critical、无Minor。统一修复后由回归与全套测试验证，没有再用一次主观复审代替测试：

| 问题 | 修复与回归 |
| --- | --- |
| 非文本codec通过规则却在CSV打开时抛异常 | 规则预检拒绝非文本codec，UTF-8/GB18030继续通过。 |
| Excel内联注音混入真实显示值 | 只拼接显示文本与富文本片段，忽略rPh。 |
| 数组公式对象及子区域缓存无法可靠表达来源 | 选区与不支持公式区域相交时明确阻断相关表，提供范围；未宣称支持此类公式。 |
| 一张工作表坏数值使其他表也丢失 | 工作表级非致命错误隔离；其他表保留，状态partial。 |
| 重定位SST绕过字符预算 | 从内容类型定位真实共享字符串；32,001字符仍全局阻断。 |
| 损坏DEFLATE流抛zlib异常 | 转为来源级invalid_zip，独立健康CSV仍可读取。 |

另外覆盖规则登记后变化、超长数值词法、伪维度、远端真实内容、实际解压大小、重复ZIP成员、宏/外部工作簿链接/实体、授权/符号链接/硬链接/特殊文件、逻辑记录及物理行、隐藏/筛选/显式排除、原数值词法与普通公式/缓存。

## 运行边界

模块状态ready仅表示当前读取阶段可继续。单表错误保留原因，整批预算或来源变化清空所有可用表。时限为循环/阶段边界协作检查，库调用期间无硬进程中断；共享元数据损坏可能阻断整个物理来源。完整执行控制留待后续CLI和宿主验证。

尚未实现或验证：真实键匹配与差异判定、结果工作簿/报告、Excel/WPS视觉、最大宽表/全链路容量、标准Skill/WorkBuddy包和真实Agent调用。

## 重现

在隔离环境安装`skills/excel-reconciliation-assistant/requirements.txt`后执行：

```sh
python3 -m unittest discover -s tests -v
python3 tools/verify_m2.py
```

前者只写系统临时合成夹具，后者额外更新本阶段证据JSON与忽略目录日志。不得运行M1构建器或finalize来“修复”摘要失败。接口与限制见[读取说明](../../docs/intake.md)。
